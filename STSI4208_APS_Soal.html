Ujian Online Uraian: Analisis dan Perancangan Sistem

Soal 1: Data Flow Diagram (DFD) - Sistem Pengelolaan Barang 45 Poin ▼
PERTANYAAN:

Manager Pergudangan pada sebuah perusahaan menetapkan akan mengembangkan otomasi di kantor cabang, yaitu pada sistem pengelolaan barang yang sedang berjalan dengan menerapkan penggunaan Barcode/QR Code scanner pada proses penempatan barang yang dikiri oleh kantor pusat sesuai pesanan kantor cabang. Penempatan barang berdasarkan Shipping List (SL) yang diterbitkan kantor pusat, sesuai pesanan kantor cabang. Hal ini untuk memastikan data pada sistem ter-update secara realtime sesaat setelah barang ditempatkaan pada lokasi tertentu.

Silahkan Anda gambarkan disertai penjelasan Data Flow Diagram (DFD) yaitu Contacts Diagram dan DFD level 1, DFD level 2 yang menggambarkan penerapan Barcode/QR Code scanner pada proses penempatan barang yang dikiri oleh kantor pusat!

Context Diagram (Konteks Diagram)
Penjelasan Context Diagram:
  • External Entity: Terdapat 3 entitas eksternal yaitu Kantor Pusat, Kantor Cabang, dan Manager Pergudangan
  • Data Flow Masuk: Shipping List (SL) dari Kantor Pusat sebagai input utama
  • Data Flow Keluar: Laporan Penerimaan ke Kantor Cabang dan Status Sistem ke Manager
DFD Level 1 - Proses Utama
Penjelasan DFD Level 1:
  • Process 1.0 - Penerimaan SL & Barang: Kantor Pusat mengirim Shipping List beserta barang-barangnya ke gudang
  • Process 2.0 - Scanning & Verifikasi QR Code: Staff menggunakan QR Code scanner untuk memverifikasi setiap barang
  • Process 3.0 - Penempatan & Update Lokasi: Barang ditempatkan sesuai lokasi dan sistem update lokasi secara real-time
  • Process 4.0 - Laporan & Arsip: Membuat laporan penerimaan untuk Kantor Cabang dan mengarsip data
  • Data Store D1: Menyimpan data barang yang diterima
  • Data Store D2: Menyimpan informasi lokasi barang di gudang
DFD Level 2 - Detail Proses Scanning & Verifikasi QR Code
Penjelasan DFD Level 2 (Sub-proses dari Process 2.0):
  • 2.1 - Scan Barcode/QR Code: Staff menggunakan scanner untuk membaca kode barang
  • 2.2 - Verifikasi ke Data Barang: Sistem memverifikasi QR code yang terbaca dengan database data barang (D1)
  • 2.3 - Update Status Barang: Jika verifikasi sukses, status barang diupdate dan dicatat di log scan (D3)
  • 2.4 - Catat Error/Discrepancy: Jika ada ketidaksesuaian, error dicatat di D4 untuk ditindaklanjuti
  • Data Store: D1 (Data Barang), D3 (Scan Log), D4 (Error Log)
💡 Keuntungan Implementasi QR Code Scanner:
  • Mengurangi human error dalam pencatatan barang
  • Mempercepat proses penerimaan barang
  • Update data real-time ke sistem
  • Tracking lokasi barang yang akurat
Soal 2: System Flow Diagram - Otomasi Pengelolaan Barang 45 Poin ▼
PERTANYAAN:

Pada sebuah perusahaan jasa pengiriman, Direktorat Operasional menetapkan akan mengembangkan otomasi pada sistem pengelolaan barang yang sedang berjalan saat ini. Otomasi dikembangkan menggunakan Barcode/QR Code scanner dan diterapkan pada proses pengeluaran barang.

Silahkan Anda gambarkan Bagan Alir Sistem disertai penjelasan yang menunjukkan proses pengeluaran barang dengan penggunaan Barcode/QR Code scanner!

System Flow Diagram - Proses Pengeluaran Barang
Penjelasan Alir Sistem Pengeluaran Barang:
  • Langkah 1-2: Terima dan verifikasi permintaan pengeluaran barang dengan cek stok di database
  • Langkah 3: Siapkan barang dari lokasi gudang yang sesuai
  • Langkah 4-5: Scan QR code barang dan update status di database menjadi "Keluar"
  • Langkah 6: Cetak surat jalan dan bukti pengeluaran resmi
  • Langkah 7-8: Serahkan barang ke penerima dengan tanda tangan konfirmasi
  • Langkah 9: Arsip dokumentasi dan update log pengeluaran untuk audit trail
⚠️ Poin Penting dalam Sistem Flow:
  • QR Code scanner digunakan untuk validasi barang sebelum keluar gudang
  • Jika scan gagal, proses diulang sampai sukses
  • Database diupdate secara real-time untuk akurasi stok
  • Dokumentasi lengkap diperlukan untuk audit dan tracking
Soal 3: Strategi Akuisisi Sistem - Solusi Teknis & Rekomendasi 10 Poin ▼
PERTANYAAN:

Pada sebuah perusahaan, Manager Pergudangan menetapkan akan mengganti sistem pengelolaan barang yang mampu menerapkan otomalisasi (penggunaan Barcode/QR Code) salah satunya proses pengambilan barang yang disesan pembeli. Pengantian sub-sistem pengelolaan pesanan pembeli pada sistem pengelolaan barang ini berdampak besar namun terdapat sumber daya yang mampu melakukan pengembangannya. Manajemen memutuskan bahwa pengantian ini adalah bersifat mendesak.

Silahkan Anda tentukan strategi akuisisi sistem baru yaitu pengembangan kustom atau paket (package) atau outsourcing yang sesuai dengan permasalahan di atas!

Analisis Situasi & Rekomendasi Strategi
📊 Analisis Kondisi Perusahaan:
  • Urgensi: Mendesak (waktu terbatas untuk implementasi)
  • Dampak: Besar (sub-sistem pengelolaan pesanan pembeli)
  • SDM Teknis: Tersedia untuk melakukan pengembangan
  • Kompleksitas: Sistem terintegrasi dengan sistem pengelolaan barang yang sudah berjalan
🎯 Rekomendasi Strategi Akuisisi: PENGEMBANGAN KUSTOM (Custom Development)

Alasan Pemilihan Custom Development:

  • Ketersediaan SDM: Perusahaan memiliki sumber daya yang mampu mengembangkan, sehingga lebih cost-effective dibanding outsourcing
  • Integrasi Sempurna: Custom development memungkinkan integrasi seamless dengan sistem pengelolaan barang yang sudah berjalan
  • Customization Penuh: Dapat disesuaikan dengan kebutuhan spesifik dan alur bisnis perusahaan
  • Kontrol Penuh: Perusahaan memiliki kontrol penuh terhadap kode, desain, dan implementasi sistem
  • Maintenance & Support: Tim internal dapat melakukan maintenance dan support langsung tanpa dependensi vendor
  • Knowledge Transfer: Tim internal dapat belajar dan mengembangkan keahlian dari proses development

📋 Rencana Implementasi Custom Development:
Fase 1: Perencanaan & Analisis (2-3 minggu)
  • Gathering requirement lengkap dari stakeholder
  • Analisis kebutuhan integrasi dengan sistem existing
  • Desain arsitektur sistem dan database
  • Perencanaan timeline dan alokasi resource
Fase 2: Desain & Pengembangan (6-8 minggu)
  • Desain detail sistem (UI/UX, API, Database)
  • Development backend dan integrasi QR code scanner
  • Development frontend untuk user interface
  • Development module pengelolaan pesanan pembeli
Fase 3: Testing & Quality Assurance (3-4 minggu)
  • Unit testing setiap module development
  • Integration testing dengan sistem yang ada
  • User acceptance testing (UAT) dengan end user
  • Performance testing dan security testing
Fase 4: Implementasi & Go-Live (2-3 minggu)
  • Data migration dari sistem lama ke baru
  • Training untuk user dan IT staff
  • Deployment ke production environment
  • Support post go-live dan optimization
✅ Keuntungan Memilih Custom Development untuk Kasus Ini:
  • SDM tersedia, sehingga lebih hemat biaya dibanding outsourcing
  • Dapat dikerjakan secara paralel dengan operasional bisnis yang berjalan
  • Integrasi sempurna dengan sistem pengelolaan barang existing
  • Timeline dapat dioptimalkan sesuai urgensi perusahaan
  • Ownership penuh untuk maintenance dan pengembangan future
  • Knowledge transfer internal meningkatkan kapabilitas tim
⚠️ Risk & Mitigasi Custom Development:
  • Risk: Keterlambatan development → Mitigasi: Gunakan project management & sprint methodology
  • Risk: Quality issues → Mitigasi: Implementasi testing automation & code review ketat
  • Risk: Resource conflict → Mitigasi: Alokasi dedicated team terpisah dari operasional
  • Risk: Budget overrun → Mitigasi: Budget contingency 20-30% dari estimasi
